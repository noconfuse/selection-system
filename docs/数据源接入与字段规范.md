# 数据源接入与字段规范（SEL-21）

> 属于 SEL-6「接入主流电商平台商品与销量数据」的第一阶段产出。
> 定义平台接入清单、合规采集口径、字段规范与采集频率，作为 SEL-22/23/24 落地实现的依据。

---

## 1. 目标与范围

通过开放 API 或合规采集方式接入主流电商平台的商品、价格、销量、评价数据，为选品系统的
「实时爆款发现 / 潜力预测 / 看板 / 预警」提供统一口径的数据底座。

本规范约束：

- 接入哪些平台/数据源（一级清单）
- 每种平台用什么方式接入（开放 API / 自有数据 / 页面采集）
- 采集到什么字段、按什么统一口径存储（统一商品模型）
- 各平台采集频率与合规约束

---

## 2. 统一商品数据模型（唯一口径）

所有数据源采集结果最终都必须转换为统一的 `Product` 模型后再写入管道（见
`sel_collector/models.py`），序列化字段（`to_kafka()`）如下：

| 内部字段 | 类型 | 必填 | 语义 | 补充说明 |
|---|---|---|---|---|
| `platform` | str | 是 | 数据源标识 | 平台名/公开榜单名，如 `jd`、`douyin` |
| `product_id` | str | 是 | 商品唯一 ID | 数据源内唯一，跨源去重键为 (platform, product_id) |
| `title` | str | 是 | 商品标题 | |
| `category` | str | 是 | 类目 | best-effort，缺省 `unknown` |
| `price` | float | 是 | 当前售价（元） | 无则填 0.0；源值为 `¥1,299.00` 等需清洗 |
| `original_price` | float? | 否 | 划线价/原价 | |
| `sales` | int | 否 | 累计销量 | `1.2万`/`5000+` 需归一化为整数 |
| `review_count` | int | 否 | 评价数 | 同上归一化 |
| `review_score` | float? | 否 | 平均评分（0-5） | |
| `spu_id` | str? | 否 | SPU ID | 平台含义各异，按现状保留 |
| `sku_id` | str? | 否 | SKU ID | 同上 |
| `listed_at` | str? | 否 | 上架时间（ISO8601） | |
| `collected_at` | str | 是 | 采集时间（UTC ISO8601） | 由系统写入，源不可覆盖 |

字段映射统一通过配置中的 `field_map` 声明，将「源字段名」映射到上表的「内部字段名」
（见 `sel_collector/base.py` 的 `DEFAULT_FIELD_MAP`）。

**缺失兜底规则**：`price` 缺省 0.0；`sales`/`review_count` 缺省 0；`category` 缺省
`unknown`；无法解析的非整数一律记 0，不允许脏数据/异常值散落各源。

## 3. 平台接入清单（一级）

> 状态标记：`[规范已定]` 表示本阶段已定义规格，实施状态见 SEL-22/23/24。

### 3.1 候选平台与接入方式

| 平台 | 首选接入方式 | 可选方式 | 主要字段可得性 | 备注 |
|---|---|---|---|---|
| 京东 | 开放平台 API（需商家/服务商授权） | 自有数据 / 页面采集(仅兜底) | 商品/价格/销量/评价均可得 | 销量数据通常仅授权商家可见 |
| 淘宝/天猫 | 淘宝开放平台 TOP API（需应用与授权） | 自有店铺数据导出 | 商品/价格/评价可得，销量受限 | 销量接口权限门槛高 |
| 抖音电商 | 抖店开放平台 API（商家授权） | 页面采集（仅兜底） | 商品/价格/销量/评价 | 需商家自建应用 |
| 拼多多 | 开放平台 API（商家授权） | 页面采集（仅兜底） | 商品/价格/销量 | 评价数据获取受限 |
| 快抖/快手小店 | 快手电商开放平台 API（商家授权） | 自有数据 | 商品/价格/销量 | 视授权范围 |
| Amazon | SP-API（需专业开发者账号） | 页面采集（仅兜底） | 商品/价格/评价 | 销量为 BSR 排名非精确销量 |
| 自有平台/店铺 | 自有后端 API / 数据文件导入 | — | 全字段 | 见 3.2，优先接入 |

> 页面采集一律为「兜底方案」，仅当平台无 API 或授权不可得时使用，且必须满足第 4 节合规约束。

### 3.2 自有平台/店铺数据（own 适配器）

- **file_path**：CSV / JSON / JSONL 数据文件，一次性导入历史数据。
- **api_url**：自有后端接口返回商品列表（支持持续增量同步），字段按 `field_map` 映射。
- 优先级最高：数据可控、无需授权、字段完整，是打通数据管道的首选。

### 3.3 公开数据源（public 适配器）

- 开放的榜单接口 / 公开数据集（CSV / JSONL）。
- 适合作为兜底与冷启动数据：可以快速产出样例数据验证链路。

### 3.4 爬虫（crawler 适配器）

- 对目标站点列表页 HTTP 抓取 + CSS selector 提取字段；URL、分页、selector、字段映射全部配置化。
- 仅针对上述候选平台中「无 API 或授权不可得」的场景实施。

## 4. 合规采集口径（硬约束）

1. **优先官方 API**：凡有开放平台 API 的平台，必须优先走授权 API，禁止未经授权绕行采集。
2. **页面采集约束**（crawler 适配器必须遵守）：
   - 遵守站点 `robots.txt` 与平台服务条款；
   - **限速**：默认 `requests_per_sec=1`，禁止多线程高压抓取；
   - 使用真实 User-Agent 与 Referer，不对抗反爬（不做验证码绕过、代理池轮换等对抗手段）；
   - 仅抓取列表页公开可见数据，不采集登录态/受限数据。
3. **数据使用边界**：仅用于内部选品分析，不外传、不提供自动下单等交易能力，符合
   《个人信息保护法》与各平台数据使用条款。
4. **频率合规**：采集频率与目标来源负载能力匹配，分钟级为上限，具体见第 5 节。

---

## 5. 采集频率规范

调度器按数据源循环执行，`interval_sec` 为两轮间隔（见 `sel_collector/scheduler.py`）。

| 数据源类型 | 默认频率 | 说明 |
|---|---|---|
| 公开数据源（public） | `interval_sec=300`（5 分钟，分钟级轮询） | 实时性要求高的榜单/异动源 |
| 自有数据 API（own/api_url） | `interval_sec=300` | 随内部数据更新节奏，可放宽到 10 分钟 |
| 自有数据文件（own/file_path） | 一次性导入 | 不轮询，落地即入 |
| 爬虫（crawler） | `interval_sec=600`（10 分钟）+ `requests_per_sec<=1` | 受站点限速约束，禁止高频 |

实现约定：

- 采集间隔在 `config.yaml` 每个 `sources[].interval_sec` 声明，不写死在代码里；
- 失败重试：单轮内退避重试 3 次（间隔 5s、10s、15s），连续失败跳过本轮并告警，不中断其他数据源；
- 单轮超时默认 15s（API 30s），长任务不允许阻塞整个管道。

---

## 6. 配置规范（config.yaml）

每个数据源一条 `sources` 记录：

```yaml
sources:
  - source: public    # public | own | crawler
    interval_sec: 300
    config:
      platform: jd              # 数据源标识（写进 Product.platform）
      api_url: ""               # 开放接口 URL（own/public）
      # 或 file_path: data/pub.csv
      list_key: items           # 接口返回列表的 key（JSON 对象时）
      field_map:                # 源字段名 -> 内部字段名
        product_id: product_id
        title: title
        category: category
        price: price
        sales: sales
        review_count: review_count
```

约束：

- `platform` 必填且全局唯一（去重键的一部分）；
- `field_map` 必填，至少覆盖 `product_id`、`title`、`price`；
- 爬虫源的 `config.list` 中 `card`/`fields` 为 CSS selector 集合，必须配 `requests_per_sec`。

## 7. 字段实施优先级（SEL-22/23/24 落地顺序）

1. **P0（必需）**：`platform`、`product_id`、`title`、`price`、`sales`、`collected_at`
2. **P1（强烈建议）**：`category`、`review_count`、`review_score`
3. **P2（视可得性）**：`original_price`、`spu_id`、`sku_id`、`listed_at`
